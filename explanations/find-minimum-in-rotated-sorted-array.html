寻找旋转排序数组中的最小值

Find Minimum in Rotated Sorted Array。这一页先讲“旋转”把数组变成了什么样子，写出 O(n) 的暴力解，再从零讲二分查找，然后回答本题唯一的关键问题：只比较 nums[m] 和 nums[r] 这两个数，怎么知道最小值在左边还是右边。最后把 r = m、l < r、向下取整这几个最容易写错的细节逐个拆开，走到 O(log n) 的标准解法。每一章只讲一个前置知识，所有 Python 语法都会单独解释。

题目

有一个长度为 n 的数组，原本按升序排好，后来被旋转了 1 到 n 次。旋转一次，就是把最后一个数搬到最前面。例如 [1,2,3,4,5,6]：

  • 旋转 4 次变成 [3,4,5,6,1,2]：最后四个数被搬到了前面；
  • 旋转 6 次变回 [1,2,3,4,5,6]：转了一整圈，回到原样。

数组里的元素互不相同，返回其中的最小值。O(n) 的解法很简单，你能写出 O(log n) 的吗？

输入: nums = [3,4,5,6,1,2] 输出: 1 输入: nums = [4,5,0,1,2,3] 输出: 0 输入: nums = [4,5,6,7] 输出: 4

约束：1 ≤ nums.length ≤ 1000，-1000 ≤ nums[i] ≤ 1000，所有整数互不相同。

01

旋转：最后 k 个搬到前面

Python 的列表（list）用方括号写。每个位置有一个下标，从 0 开始；负数下标从后往前数：

nums = [1, 2, 3, 4, 5, 6]
nums[0]       # 1
nums[-1]      # 6，最后一个
len(nums)     # 6，一共几个数

切片：取出一段

nums[1:4]     # [2, 3, 4]，从下标 1 到下标 3，不包含 4
nums[:2]      # [1, 2]，省略开头：从头开始
nums[2:]      # [3, 4, 5, 6]，省略结尾：一直取到最后
nums[-2:]     # [5, 6]，最后 2 个
nums[:-2]     # [1, 2, 3, 4]，除了最后 2 个
[1, 2] + [3]  # [1, 2, 3]，两个列表用 + 拼成一个
  • nums[a:b] 取下标 a 到 b - 1，不包含 b，和 range(a, b) 一样“含头不含尾”。切片得到的是一个新列表，原来的 nums 不变。
  • 旋转一次把最后一个数搬到最前面，旋转 k 次就是把最后 k 个数整体搬到最前面：nums[-k:] + nums[:-k]。

点不同的 k，看 [1, 2, 3, 4, 5, 6] 转完的样子（柱子越高，数越大；绿色是最小值）：

旋转后的数组长什么样

不管转几次，结果都是两段升序拼在一起：

  • 左段是原来末尾的 k 个数，也就是整个数组里最大的 k 个；右段是原来开头的 n - k 个数，是小的那些。所以左段的每个数都比右段的每个数大。
  • 两段交界的地方叫断点：nums[i - 1] > nums[i]。整个数组只有这一处“前一个比后一个大”，其他地方都是越往右越大。
  • 最小值就在断点右边，是右段的第一个数，下标正好是 k。
  • 转 n 次（转回原样）时没有断点，整个数组就是一段升序，最小值是 nums[0]。

所以这道题其实就是在找断点。下一章先用最直接的办法找。

02

暴力解与 O(log n)

最直接的办法：从头看到尾，一直记着见过的最小值。

res = nums[0]
for x in nums:
    if x < res:
        res = x
return res
  • for x in nums: 直接遍历列表里的值：x 依次等于 nums[0]、nums[1]、……。不需要下标时这样写最简洁。
  • Python 自带 min(nums)，一行就能拿到最小值，它内部做的也是同样的事：每个数看一遍。
  • 也可以直接找断点：第一个比前一个数小的位置就是最小值；一个都找不到，说明整个数组有序，返回 nums[0]。
for i in range(1, len(nums)):
    if nums[i] < nums[i - 1]:      # 断点
        return nums[i]
return nums[0]                     # 没有断点：整个数组有序

这几种写法最坏都要看完全部 n 个数，时间是 O(n)。题目想要 O(log n)。

O(log n) 有多快

log₂ n 的意思是：n 反复除以 2，要除几次才变成 1。比如 8 → 4 → 2 → 1，除了 3 次，所以 log₂ 8 = 3。2¹⁰ = 1024，所以 log₂ 1000 约等于 10。

数组长度 nO(n)：每个数看一遍O(log n)：每次扔掉一半
66 次约 3 次
10001000 次约 10 次
100 万100 万次约 20 次
10 亿10 亿次约 30 次

要做到 O(log n)，每一步都得扔掉大约一半的候选，直到只剩一个。“每次扔掉一半”最典型的算法就是二分查找，下一章从头讲。

03

二分查找：每次扔掉一半

先放下旋转，看最基本的问题：在一个有序数组里找 target，返回它的下标，找不到返回 -1。

用左指针 l 和右指针 r 圈出“target 可能在的范围”，每次看范围正中间的数 nums[m]：

情况做法原因
nums[m] == target返回 m找到了
nums[m] < targetl = m + 1数组有序，m 和它左边的数都 ≤ nums[m] < target，全部扔掉
nums[m] > targetr = m - 1m 和它右边的数都 ≥ nums[m] > target，全部扔掉
l, r = 0, len(nums) - 1
while l <= r:
    m = (l + r) // 2
    if nums[m] == target:
        return m
    elif nums[m] < target:
        l = m + 1
    else:
        r = m - 1
return -1
  • l, r = 0, len(nums) - 1 是同时赋值：l 等于 0，r 等于最后一个下标。
  • // 是整除：除完只留整数部分，往小的方向取。7 // 2 是 3，6 // 2 也是 3。下标必须是整数，写成 / 会得到 3.5 这样的小数，nums[3.5] 直接报 TypeError。
  • (l + r) // 2 是 l 和 r 正中间的位置。l 到 r 有偶数个数时没有正中间，取靠左的那个。
  • while l <= r：l == r 时范围里还剩一个数，它也可能是 target，检查完才能停。l 跑到 r 右边，范围就空了。
  • if / elif / else 从上往下检查，第一个成立的分支执行，其余跳过。每一轮要么找到并返回，要么扔掉一半，所以大约 log₂ n 轮就结束。

04
和最右边的数比

  
回到本题。二分的每一步只需要回答一个问题：最小值在 m 的左边还是右边？

  
我们看不见断点在哪，但可以拿 nums[m] 和范围最右边的 nums[r] 比一下。第 01 章说过：左段的每个数都比右段大，同一段里越往右越大。所以只有两种结果：

  

    
比较结果说明什么最小值在哪做法

    
nums[m] > nums[r]m 在左段，r 在右段，断点夹在 m 和 r 之间m 右边。nums[m] 本身比 nums[r] 大，不可能是最小值l = m + 1

    
nums[m] < nums[r]从 m 到 r 一路上升，中间没有断点m 本身，或者 m 左边。m 右边的数都比 nums[m] 大r = m

  

  
    
    
  • 第一行为什么成立：如果 m 和 r 在同一段，m 在 r 左边，nums[m] 应该比 nums[r] 小。现在 nums[m] 反而更大，只能是两个数隔着断点。
    • 
    
  • 第二行为什么成立：如果 m 和 r 之间有断点，m 就在左段、r 在右段，nums[m] 会比 nums[r] 大，和“nums[m] < nums[r]”矛盾。所以 m 到 r 是一段升序。
    • 
    
  • 第二行要留下 m：m 可能正好落在断点右边，它自己就是最小值，所以写 r = m，不写 r = m - 1。第 06 章用反例说明。
    • 
    
  • 不会相等：元素互不相同，而 m 一定在 r 左边（第 06 章证明），所以只有大于、小于两种情况，一个 if / else 就够了。
    • 
  

  
下面 l 固定为 0，r 固定为最后一个下标。点任意一根柱子当 m（不一定是中间），看比较结果会扔掉哪一边。虚线绿框是真正的最小值，看看它是不是总留在剩下的范围里：

  

    

      

    

    
    

    
lm（点柱子换）r真正的最小值

    

  

  
m 选在哪里，判断都成立。二分专门选正中间，是为了不管走哪个分支都能扔掉一半，O(log n) 就是这么来的。

  
扔掉一部分之后，剩下的 [l, r] 本身还是一个“旋转排序数组”：要么还是两段升序，要么只剩一段升序。所以下一轮可以用完全相同的判断，一直缩到只剩一个数。







  
05
为什么不和最左边比

  
很自然会想：为什么不拿 nums[m] 和最左边的 nums[l] 比？看两个数组，l = 0，m = 2：

  

    

      [1, 2, 3, 4, 5]
      

      
转了 5 次，回到原样。nums[m] = 3 > nums[l] = 1，最小值在 m 的左边（下标 0）。

    

    

      [3, 4, 5, 1, 2]
      

      
转了 2 次。nums[m] = 5 > nums[l] = 3，最小值在 m 的右边（下标 3）。

    

  

  
同样是 nums[m] > nums[l]，最小值一个在左、一个在右，只凭这一次比较决定不了扔哪边。nums[m] > nums[l] 只说明 l 到 m 是上升的，断点可能在 m 右边，也可能根本没有断点。

  
换成和 nums[r] 比，两个数组都能判断对：

  

    
数组nums[m] 和 nums[r]做法结果

    
[1, 2, 3, 4, 5]3 < 5r = m，往左找最小值 1 确实在左边

    
[3, 4, 5, 1, 2]5 > 2l = m + 1，往右找最小值 1 确实在右边

  

  
区别在于参照物属于哪一段。最小值始终在 [l, r] 里，而 r 在最小值的右边（或者就是它），所以 nums[r] 一定在右段。拿一个确定在右段的数当参照，nums[m] 比它大就是左段，比它小就是右段，不会含糊。nums[l] 就不一样了：有断点时它在左段，没有断点时它就是最小值本身，事先不知道它属于哪一段。

  
NeetCode 视频里的解法其实是和 nums[l] 比的，但它先多做一步检查：如果 nums[l] < nums[r]，说明这一段已经有序，最小值就是 nums[l]，直接结束。排除了“没有断点”这种情况，和 nums[l] 比就不含糊了。第 08 章给出这个版本。







  
06
边界：一个字符的差别

  
把前两章拼起来，标准解法只有 8 行：


l, r = 0, len(nums) - 1
while l < r:
    m = (l + r) // 2
    if nums[m] > nums[r]:      # m 在左段，最小值在 m 右边
        l = m + 1
    else:                      # m 到 r 是升序，最小值是 m 或在 m 左边
        r = m
return nums[l]

  
它和第 03 章的二分长得很像，但有三个地方改一个字符就会出错。


  
1. r = m，不是 r = m - 1

  
nums[m] < nums[r] 时，m 本身可能就是最小值。看 [3, 1, 2]：l = 0，r = 2，m = 1。nums[1] = 1 < nums[2] = 2，走 else。如果写 r = m - 1 = 0，下标 1 上的最小值 1 就被扔掉了，最后返回 nums[0] = 3。

  
第 03 章找 target 时可以写 r = m - 1，是因为那里已经检查过 nums[m] != target，m 确定没用了。这里只比较了 nums[m] 和 nums[r]，没法确认 nums[m] 是不是最小值，只能留着它。


  
2. while l < r，不是 l <= r

  
循环里一直保持着一件事：最小值在 [l, r] 范围里。l == r 时范围里只剩一个数，它就是答案，该停了，然后 return nums[l]。

  
写成 l <= r，l == r 时还会再进一轮：m = (l + r) // 2 = l，nums[m] 和 nums[r] 是同一个数，nums[m] > nums[r] 不成立，走 else，r = m，r 没变。下一轮一模一样，死循环。每个输入最后都会走到 l == r，所以这个写法对任何输入都会死循环。


  
3. m 向下取整

  
l < r 时，(l + r) // 2 向下取整，m 最大也只能是 r - 1，一定小于 r。这保证了两件事：

  
    
    
  • nums[m] 和 nums[r] 是两个不同位置上的数，元素互不相同，所以不会相等。
    • 
    
  • 两个分支都会让范围变小：l = m + 1 让 l 变大，r = m 让 r 变小。范围每轮都在缩小，循环一定会结束。
    • 
  

  
如果改成向上取整 (l + r + 1) // 2，只剩两个数（r = l + 1）时 m = r，走 else 之后 r = m 还是原来的 r，又是死循环。

  
Java、C++ 里常写 m = l + (r - l) / 2，结果和 (l + r) / 2 一样，好处是 l + r 很大时不会整数溢出。Python 的整数没有上限，不用担心这个。


  
二分的两种写法

  

    
找 target（第 03 章）找最小值（本题）

    
循环条件while l <= rwhile l < r

    
缩小右边界r = m - 1r = m

    
m 能不能扔能：已经确认 nums[m] 不是 target不能：nums[m] 可能就是最小值

    
循环结束时范围空了，说明没找到l == r，剩下的就是答案

class Solution:
    def findMin(self, nums: List[int]) -> int:
        l, r = 0, len(nums) - 1
        while l < r:                   # 剩下不止一个候选
            m = (l + r) // 2           # 向下取整，保证 m < r
            if nums[m] > nums[r]:      # m 在左段，最小值在 m 右边
                l = m + 1
            else:                      # m 到 r 是升序，最小值是 m 或在 m 左边
                r = m
        return nums[l]                 # l == r，只剩一个候选


class Solution {
    public int findMin(int[] nums) {
        int l = 0, r = nums.length - 1;
        while (l < r) {
            int m = l + (r - l) / 2;
            if (nums[m] > nums[r]) {
                l = m + 1;
            } else {
                r = m;
            }
        }
        return nums[l];
    }
}

class Solution: 和 def findMin(self, nums: List[int]) -> int: 是 NeetCode 给定的外壳。List[int] 表示整数列表，-> int 表示返回一个整数，这些只是类型提示，不影响运行。注意返回的是最小值本身 nums[l]，不是下标 l。


  
另一种写法：NeetCode 视频里的版本


class Solution:
    def findMin(self, nums: List[int]) -> int:
        res = nums[0]
        l, r = 0, len(nums) - 1

        while l <= r:
            if nums[l] < nums[r]:          # 这一段已经有序
                res = min(res, nums[l])
                break

            m = (l + r) // 2
            res = min(res, nums[m])        # 先把 nums[m] 记下来，后面就能扔掉 m
            if nums[m] >= nums[l]:         # m 在左段
                l = m + 1
            else:                          # m 在右段
                r = m - 1
        return res

  
    
    
  • 每轮先检查 nums[l] < nums[r]：成立说明 [l, r] 里没有断点，最小值就是 nums[l]，记下来，break 跳出循环。
    • 
    
  • 不成立说明 [l, r] 里有断点（或者只剩一个数），这时 nums[l] 一定在左段，和它比就不含糊了：nums[m] >= nums[l] 说明 m 也在左段，最小值在右边；否则 m 在右段，最小值是 m 或在 m 左边。
    • 
    
  • min(a, b) 返回两者中较小的那个。res 一直记着见过的最小值，nums[m] 已经记过了，所以可以写 r = m - 1 和 while l <= r，和本页的写法刚好相反。
    • 
    
  • 这里必须写 >=：只剩两个数时 m == l，nums[m] 和 nums[l] 是同一个数，此时 m 在左段，要往右走。写成 >，[2, 1] 会返回 2。
    • 
  

  
两种写法都是 O(log n)。本页的写法更短，也不需要额外的 res 变量。


  
复杂度

  

    
解法时间额外空间说明

    
从头看到尾 / min(nums)O(n)O(1)每个数都要看一遍

    
二分，和 nums[r] 比O(log n)O(1)每轮扔掉一半，n = 1000 时最多 10 轮

最容易写错的六个地方

  
    
    
  • 写成 r = m - 1：[3, 1, 2] 把最小值扔掉，返回 3。
    • 
    
  • 写成 while l <= r：l == r 时 r = m 原地不动，任何输入都死循环。
    • 
    
  • 和 nums[l] 比，又没有先检查有序：[1, 2, 3, 4, 5] 返回 4。
    • 
    
  • 写成 m = (l + r + 1) // 2：只剩两个数时 m == r，[3, 1, 2] 死循环。
    • 
    
  • 写成 m = (l + r) / 2：Python 里 / 得到小数，nums[m] 报 TypeError。
    • 
    
  • 最后写成 return l：题目要的是最小值，不是它的下标。

同类题型：搜索旋转排序数组（Search in Rotated Sorted Array）同样先判断 m 落在哪一段，再决定扔哪边；寻找旋转排序数组中的最小值 II 允许重复值，nums[m] == nums[r] 时判断不了，只能 r -= 1，最坏退化成 O(n)；二分查找（Binary Search）、寻找峰值（Find Peak Element）也都是“看一眼中间，扔掉一半”。
