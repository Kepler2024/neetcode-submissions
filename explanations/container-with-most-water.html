盛最多水的容器

Container With Most Water。前半部分讲这道题：面积怎么算，暴力解为什么慢，“每一步扔掉短板”为什么对，再用一张“所有组合的矩阵”说明双指针不会漏掉答案。后半部分跳出这道题，总结双指针的通用思路，用一整章讲清三数之和的去重到底在做什么，最后给一份边界检查清单。

题目

给你一个整数数组 heights，heights[i] 是第 i 根柱子的高度。

任选两根柱子，和底边一起组成一个容器。返回容器最多能装多少水。

输入: heights = [1,7,2,5,4,7,3,6] 输出: 36 解释: 选下标 1（高 7）和下标 7（高 6），宽 7 - 1 = 6， 水面最高只能到矮的那根 6，面积 6 × 6 = 36 输入: heights = [2,2,2] 输出: 4

约束：2 ≤ heights.length ≤ 1000，0 ≤ heights[i] ≤ 1000。

01

面积：宽 × 短板

选定左边的下标 l 和右边的下标 r（l < r）。水面不能高过矮的那根，否则水会从矮的那边漏出去。所以：

宽度 = r - l 高度 = min(heights[l], heights[r]) 面积 = min(heights[l], heights[r]) × (r - l)
  • 宽度是下标之差 r - l。下标 1 和下标 7 之间是 6 个单位宽，不是 7。r - l + 1 是 [l, r] 这一段里有几个元素，是另一回事，第 09 章会再对比。
  • 高度由矮的那根决定，就像木桶的短板。高的那根再高也没用。下面把矮的那根叫“短板”。
  • 中间的柱子不影响结果。题目把柱子看成没有厚度的竖线，中间的柱子既不挡水也不占地方。这一点和“接雨水”（Trapping Rain Water）不一样。
  • min(a, b) 返回较小的那个，max(a, b) 返回较大的那个，都是 Python 内置函数。

点任意两根柱子，看它们组成的容器。也可以改数组：

试试下标 1 和 5：两根都是 7，比 (1, 7) 高，但宽度只有 4，面积 28，反而更小。面积要同时看宽和高，只盯着最高的柱子是不行的。

02

暴力解：试所有的对

res = 0
for l in range(len(heights)):
    for r in range(l + 1, len(heights)):
        area = min(heights[l], heights[r]) * (r - l)
        res = max(res, area)
return res
  • range(l + 1, len(heights)) 依次产生 l + 1 到 n - 1。r 从 l + 1 开始，保证 l < r，每一对只试一次。
  • res = max(res, area) 是“打擂台”：res 记着目前见过的最大值，新来的比它大就换掉它。

n 根柱子一共有 n(n-1)/2 对，时间 O(n²)。n = 1000 时约 50 万对，还能通过；LeetCode 原题 n 最多 10⁵，约 50 亿对，会超时。面试时写出暴力解之后，面试官会接着问能不能做到 O(n)。

暴力解慢在它把每一对都老老实实算了一遍，可其中绝大多数一眼就能看出不可能最大。下一章的双指针每算一对，就能证明“某根柱子剩下的组合全都不用算了”，一次排除一大片。

03

双指针：每次扔掉短板

从最宽的一对开始：l = 0，r = n - 1。宽度已经是最大了，之后不管怎么移动，宽度都只会变小。想让面积变大，只能指望高度变高。

算完 (l, r) 之后，假设左边是短板：heights[l] ≤ heights[r]。看 l 和 r 左边任何一根柱子 r'（l < r' < r）组成的容器：

面积(l, r') = min(heights[l], heights[r']) × (r' - l) ≤ heights[l] × (r' - l) 高度不会超过短板 heights[l] < heights[l] × (r - l) 宽度更小 = 面积(l, r) heights[l] 本来就是 (l, r) 的短板

也就是说，l 剩下的所有组合都不会比刚算出的 (l, r) 更大。l 已经“用完了”，可以放心扔掉：l += 1。右边是短板时同理，扔掉 r：r -= 1。

用示例 1 验证第一步

heights = [1,7,2,5,4,7,3,6]，l = 0（高 1），r = 7（高 6），面积 min(1, 6) × 7 = 7，左边是短板。把下标 0 和其他柱子的组合全算出来：

和谁配宽高 min(1, …)面积
下标 1（高 7）111
下标 2（高 2）212
下标 3（高 5）313
下标 4（高 4）414
下标 5（高 7）515
下标 6（高 3）616
下标 7（高 6）717，就是刚算的这一对

高度被 1 卡死，宽度又在变小，下标 0 不可能出现在比 7 更大的容器里。

为什么不能扔掉高的那根

如果第一步扔掉的是 r = 7（高 6），它和下标 1（高 7）组成的 (1, 7) 面积是 36，正是答案，就再也算不到了。上面那串不等式只对短板成立：短板的高度卡住了它所有的组合；高板的组合里可能出现一根更高的新柱子，没法证明它们都更小。

换个角度看：扔掉高板之后，下一个容器的高度仍然不超过当前的短板，宽度还少了 1，面积一定更小。这一步纯属浪费。

一样高的时候

heights[l] == heights[r] 时，两边都是短板，上面的推理对两边都成立：l 剩下的组合、r 剩下的组合都不会更大。所以扔哪边都行，两边一起扔也行。NeetCode 的写法是 if heights[l] <= heights[r]: l += 1，相等时扔左边。

每一步扔掉一根柱子，n 根柱子扔 n - 1 次就只剩一根，循环结束。所以一共只算了 n - 1 对，时间 O(n)。

04

矩阵视角：为什么不会漏

把所有的对排成一张表：第 l 行、第 r 列的格子就是 (l, r) 的面积。只有 l < r 的右上半部分有意义。示例 1 一共 7 + 6 + … + 1 = 28 格，暴力解就是把这 28 格全算一遍，绿色是最大的 36。

heights = [1,7,2,5,4,7,3,6]，行是 l，列是 r

双指针从右上角 (0, 7) 出发。还没被排除的格子永远是一个三角形：l ≤ 行 < 列 ≤ r，当前的 (l, r) 正好是这个三角形的右上角。

  • l += 1 等于删掉三角形最上面的一整行。第 l 行剩下的格子都在 (l, r) 的左边，宽度更小、高度被短板卡住，都不会更大。
  • r -= 1 等于删掉最右边的一整列，道理相同。
  • 每步删一行或一列，三角形越缩越小，路线像下楼梯一样从右上角走到对角线，一共 n - 1 步。

打开上面的开关：双指针只算了 7 格，但这 7 格里有最大值。被删掉的每一格，都有“它不会比某个算过的格子更大”的证明，所以不会漏。

这张表是理解所有“对撞双指针”的钥匙。两数之和 II 用的也是同一张表：和太大就删一列，和太小就删一行。不同的题只是“凭什么删”的理由不同，第 07 章会把它们放在一起比。

完整代码与复杂度

  

    
    
    
  


class Solution:
    def maxArea(self, heights: List[int]) -> int:
        l, r = 0, len(heights) - 1                        # 从最宽的一对开始
        res = 0

        while l < r:
            area = min(heights[l], heights[r]) * (r - l)  # 短板 × 宽度
            res = max(res, area)
            if heights[l] <= heights[r]:                  # 左边是短板（或一样高）
                l += 1                                    # 扔掉左边
            else:
                r -= 1                                    # 扔掉右边
        return res


class Solution {
    public int maxArea(int[] heights) {
        int l = 0, r = heights.length - 1;
        int res = 0;
        while (l < r) {
            int area = Math.min(heights[l], heights[r]) * (r - l);
            res = Math.max(res, area);
            if (heights[l] <= heights[r]) {
                l++;
            } else {
                r--;
            }
        }
        return res;
    }
}


class Solution {
public:
    int maxArea(vector<int>& heights) {
        int l = 0, r = (int)heights.size() - 1;
        int res = 0;
        while (l < r) {
            int area = min(heights[l], heights[r]) * (r - l);
            res = max(res, area);
            if (heights[l] <= heights[r]) {
                l++;
            } else {
                r--;
            }
        }
        return res;
    }
};

  
List[int] 和 -> int 是类型提示，表示参数是整数列表、返回整数，不影响运行。

07
双指针的通用思路

  
双指针就是用两个下标变量在同一个数组（或字符串、链表）上移动。两个指针都只朝一个方向走、从不回头，加起来最多走 n 步，所以原本要两层循环才能看完的东西，一层循环就看完了。按两个指针怎么走，常见的有三类：

  

    
类型两个指针怎么走典型题

    
对撞指针一个从最左、一个从最右，相向往中间走，相遇就停验证回文串、两数之和 II、三数之和、盛最多水的容器

    
快慢指针都从左边出发、同向走：一个负责读一个负责写，或者一个走两步一个走一步删除有序数组中的重复项、移动零、环形链表

    
滑动窗口同向走，l 和 r 夹着一段连续区间，r 负责扩张，l 负责收缩无重复字符的最长子串、买卖股票的最佳时机

  

  
这一页和你做过的验证回文串、三数之和用的都是第一种，下面只讲对撞指针。


  
核心：每一步排除一端

  
对撞指针本质上是在第 04 章那张“所有对”的表上做排除法。下面是伪代码模板，if 里那句是要你自己想清楚的部分：


l, r = 0, len(nums) - 1
while l < r:
    # 1. 看 (l, r) 这一对：记录答案，或者做判断
    # 2. 想清楚：看完这一对之后，哪一端已经不可能出现在（更好的）答案里？
    if 左端没用了:
        l += 1        # 删掉一行
    else:
        r -= 1        # 删掉一列

  
难点只有一个：看完 (l, r) 之后，凭什么能确定某一端没用了？能回答，就能用对撞指针；回答不了，就不能用。这个理由总是来自某种单调性：两数之和 II 来自“数组有序”，盛水来自“从最宽开始，宽度只减不增”。

  

    
题看 (l, r) 时比较什么什么时候扔 l凭什么

    
验证回文串s[l] 和 s[r]相等时两端一起扔这一对已经配好，不会再用；不相等直接返回 False

    
两数之和 IInums[l] + nums[r] 和 target和 < target数组有序，nums[l] 和最大的 nums[r] 配都不够，和谁配都不够

    
三数之和固定 nums[i]，其余同上和 < 0同上

    
盛最多水的容器两根柱子的高度heights[l] ≤ heights[r]l 剩下的组合宽度更小、高度被它卡住，不会更大

  

  
盛水这道题不能排序：排序会打乱柱子的位置，宽度就全错了。它的单调性来自宽度，不来自数值大小。看到“对撞指针”不要条件反射先 sort，先想清楚单调性从哪来。

  2. 从哪里出发？对撞指针几乎总是 0 和 n - 1，因为最外面那一对是矩阵的右上角，从这里出发每一步都能删一整行或一整列。

    4.

08
去重：只跟兄弟比

  
先说结论：盛最多水的容器不需要去重，它只返回一个数，同一个最大值算两次也还是它。只有“返回所有组合，组合按值算、不能重复”的题才要去重。这一章用三数之和来讲。


  
什么时候需要去重

  

    
题返回什么要去重吗

    
盛最多水的容器一个数（最大面积）不需要

    
验证回文串True / False不需要

    
两数之和 II一对下标，题目保证只有一个解不需要

    
三数之和所有值不同的三元组需要

    
四数之和所有值不同的四元组需要，每一层都套同一条规则

  


  
一层的去重：每段相同值只派一个代表

  
排好序之后，相同的值一定挨在一起，形成一段一段。要让每个值只出现一次，就让每一段只派第一个当代表，其余的跳过。怎么认出“这一段的第一个”？它和左边的邻居不同，或者它左边根本没有邻居：


for p in range(len(nums)):
    if p > 0 and nums[p] == nums[p - 1]:
        continue            # 和左边同值：这一段已经派过代表了
    print(nums[p])          # 每个值只打印一次

  

  
p > 0 的意思是：p 不是第一个候选时，才拿它和左边比。p = 0 左边没有东西，不需要比。在 Python 里漏写它，程序不会报错：nums[-1] 会读到最后一个数，然后悄悄算错。后面会看到，这个“不是第一个候选”的条件，正是三数之和去重的关键。


  
三层的去重：把三数之和画成一棵树

  
三数之和要选三个数，可以看成依次做三次选择：第 1 层选第一个数，第 2 层在它右边选第二个，第 3 层再往右选第三个。从根走到叶子的每一条路，就是一组下标 i < j < k。下面的树默认是排好序的 [-1, -1, 0, 1, 2]，先看“不去重”：

  

    
    
    

    
    

      
      
      
    

    

    

  

  
节点里大的数字是值，小的 [ ] 是下标。紫框是第 1 个数（i），琥珀框是第 2 个数（l），蓝框是第 3 个数（r）。叶子下面写着这条路选出的三个数和它们的和：绿色是和为 0 的答案，红色是重复的答案。树里最多 6 个数，每个数在 -9 到 9 之间，方便画得下。

  
“不去重”时，两个 -1 都在第 1 层当了第一个数，它们下面长出了一样的分支，于是 [-1, 0, 1] 出现了两次。


  
关键：只跟兄弟比，不跟父亲比

  
树里有两种“相邻的同值”，处理方式正好相反：

  

    
关系例子（[-1, -1, 0, 1, 2]）能不能剪

    
兄弟：同一层、同一个父节点下第 1 层的 -1[0] 和 -1[1]剪掉后面那个。两个兄弟下面的分支一模一样，后一个只会造出重复

    
父子：上一层和下一层第 1 层选 -1[0]，第 2 层选 -1[1]不能剪。[-1, -1, 2] 就需要它，两个 -1 用在了不同的位置上

  

  
所以完整的规则是：每一层有自己的起点 start（这一层第一个候选的下标），位置 p 只在不是本层第一个候选时，才和左边比：

  
跳过 p   ⇔   p > start  并且  nums[p] == nums[p - 1]

  
p > start 保证了 nums[p - 1] 是同一层的兄弟。p == start 时，左边的 nums[p - 1] 正好是上一层选中的父亲，不能拿来比。把上面的开关切到“连父亲一起比”，[-1, -1, 2] 就被误剪掉了。

  

    
树的第几层start在 [-1, -1, 2] 上

    
第 1 层（选 i）0p = 0 是本层第一个，不比，选第一个 -1；p = 1 和左边同值，跳过

    
第 2 层（i = 0 下面）i + 1 = 1p = 1 是本层第一个，不比。左边的 nums[0] 是它的父亲，不是兄弟。选第二个 -1，凑出 [-1, -1, 2]

  


  
为什么留第一个，而不是留最后一个

  
同一层里两个同值的兄弟 p < q。q 的分支只能从 q 右边选数；p 的分支能从 p 右边选，范围更大，还包含 q 本身。所以 q 能凑出的每一种值组合，p 都能凑出来；反过来不成立，因为 p 的分支可以把 q 当成下一个数用。留下范围最大的第一个，扔掉的只会造出重复，一个答案都不会少。

  
如果改成和后一个比（nums[i] == nums[i + 1] 就跳过），留下的就是每段的最后一个，范围最小。[-1, -1, 2] 里第一个 -1 被跳过，第二个 -1 右边只剩一个 2，凑不出答案。


  
对应回三数之和的代码

  
双指针版本没有真的把树画全，但去重用的是同一条规则：

  

    
层选的是start代码里怎么写

    
第 1 层nums[i]0if i > 0 and nums[i] == nums[i - 1]: continue，就是 p > start 那条规则

    
第 2 层nums[l]i + 1找到一组后先 l += 1，再 while l < r and nums[l] == nums[l - 1]: l += 1

  • 第 2 层为什么写在 append 之后？双指针里 l 只往右走。和不等于 0 时遇到重复的 l，只是多比一次，不会记下答案；只有刚记下一组答案之后，下一个同值的 l 才会把同一组再记一次。所以只在找到之后跳。这时 l 已经加过 1，一定满足 l > i + 1，nums[l - 1] 是刚用过的兄弟，不是父亲 nums[i]。
    • 
    
  • 第 3 层为什么不用写？i 和 l 定了，第三个数必须等于 -(nums[i] + nums[l])，同值的 r 只是同一个值的不同位置。l 跳到新的值之后，旧的 r 会因为和大于 0 被正常流程挪走。对称地也给 r 写一个跳过，结果一样。

#规则写错时会怎样例子

    
1右指针从最后一个下标开始：r = len(nums) - 1写成 len(nums)，第一次读 nums[r] 就 IndexError长度为 n 的列表，下标是 0 到 n - 1

    
2两个指针必须指向不同位置时，用 while l < r写成 l <= r，同一个位置被用两次三数之和 l == r 时会把同一个数当两个数用。盛水 l == r 时宽度是 0，多算一次虽然无害，但没有意义。二分查找这种单个位置也要检查的题才用 <=

    
3每一轮至少移动一个指针某个分支谁都不动，死循环盛水写成 if < / elif > 没有 else，[2, 2, 2] 卡在相等上

    
4内层 while 要带上外层的条件 l < r内层循环一路走过头，越界或指针交错验证回文串的 "!!!"；三数之和找到后跳重复时的 [0, 0, 0]

    
5读 nums[p - 1] 之前，确认它是你想比的那个Python 的 nums[-1] 不报错，悄悄读到最后一个数；或者把父亲当成了兄弟去掉 i > 0，[0, 0, 0] 返回 []

    
6想清楚“先用、再移、再跳”的顺序跳重复写在 append 前面，或者移动之前就比较，会漏答案或者出重复三数之和：append → l, r = l + 1, r - 1 → 拿新的 nums[l] 和刚用过的 nums[l - 1] 比

    
7距离是 r - l，个数是 r - l + 1结果多 1盛水 [1, 1] 的答案是 1；区间 [l, r] 里有 r - l + 1 个元素
