买卖股票的最佳时机

Best Time to Buy and Sell Stock。这一页先用暴力解把所有“哪天买、哪天卖”的组合摆出来，再问一个问题：卖出日定了，该哪天买？这个问题的答案有两种写法。一种是双指针：l 记买入日，r 扫卖出日。另一种是动态规划（DP）：从爬楼梯讲起，把“状态、转移、初始值、答案”四步讲清楚，再用同样的四步解本题。最后你会看到，这两种写法其实是同一个算法。

题目

给你一个整数数组 prices，prices[i] 是 NeetCoin 在第 i 天的价格。

你可以选某一天买入一个 NeetCoin，再选之后的另一天卖出。返回能获得的最大利润。你也可以不做任何交易，这时利润是 0。

输入: prices = [10,1,5,6,7,1] 输出: 6 解释: 第 1 天以 1 买入，第 4 天以 7 卖出，利润 7 - 1 = 6 输入: prices = [10,8,7,5,2] 输出: 0 解释: 价格一路下跌，怎么买卖都亏，不交易，利润 0

约束：1 ≤ prices.length ≤ 100，0 ≤ prices[i] ≤ 100。

01

先买后卖

利润 = 卖出价 − 买入价。题目有两条规则：

  • 先买后卖：买入日 i 必须早于卖出日 j，也就是 i < j。同一天买卖利润是 0，等于没交易。
  • 可以不交易：所以答案至少是 0。价格一路下跌时，任何买卖都亏钱，答案就是 0。

第一反应往往是“最高价减最低价”。用例 1 试一下（柱子越高价格越高，柱子下面的数字是第几天）：

最高价 − 最低价 = 10 − 1 = 9 ✗

最高价 10 在第 0 天，最低价 1 在第 1 天。要赚这 9 块，得第 1 天买、第 0 天卖，是先卖后买，不允许。

第 1 天买，第 4 天卖 = 7 − 1 = 6 ✓

虚线是买入价 1。卖出那天的柱子比虚线高出来的绿色部分就是利润，这里是 6。

这道题难在时间顺序：只能拿“后面的高价”减“前面的低价”。最高价出现在最低价前面时，最高减最低就错了。后面所有方法都在处理这一点。

02

暴力解：试遍每一对

最直接的办法：把每一对（买入日 i，卖出日 j）都试一遍，j 必须在 i 后面。

res = 0                                  # 不交易，利润 0
for i in range(len(prices)):             # i：买入日
    for j in range(i + 1, len(prices)):  # j：卖出日，从 i 的下一天开始
        res = max(res, prices[j] - prices[i])
return res
  • range(a, b) 依次给出 a、a + 1、……、b − 1，不含 b。range(n) 是 range(0, n) 的简写。
  • 内层从 i + 1 开始，保证 j > i：卖出日一定在买入日之后。上一章说的“时间顺序”，在代码里就是这一个 + 1。
  • max(a, b) 返回较大的那个。res 一直记着见过的最大利润。它从 0 开始，表示“不交易”；如果每一对都亏钱，res 停在 0，正好是题目要的答案。
  • 一共试 n(n − 1) / 2 对，时间 O(n²)。本题 n ≤ 100，最多 4950 对，能通过；LeetCode 上同一题 n 可以到 10⁵，要试约 50 亿对，会超时。

03

固定卖出日

看上一章表格的某一列。卖出日 j 定了，prices[j] 就定了，这一列每个格子都是 prices[j] − prices[i]，变的只有买入价 prices[i]。要让差最大，prices[i] 就要最小。

卖出日是 j 时，最好的买入日就是 j 前面最便宜的那一天。

点任意一根柱子，把它当卖出日。j 后面的日子还没到，画成淡色；琥珀色是 j 前面最便宜的那天：

卖出日 j（点柱子换）j 前面最便宜的那天利润淡色：j 之后，还没到
卖出日 jprices[j]之前最低价最多赚

于是问题变成：对每个卖出日 j，求出“j 之前的最低价”，再取 prices[j] − 最低价 的最大值（和 0 比，取大）。

“j 之前的最低价”怎么求？看表格第三列：第 j 行只比第 j − 1 行多考虑了一个数 prices[j − 1]。

j 之前的最低价 = min( j − 1 之前的最低价, prices[j − 1] )

所以从左往右走一遍，边走边更新最低价，不用每次回头重找。O(n²) 就变成了 O(n)。这个想法有两种写法：

  • 用两个下标 l、r 来写，就是双指针（第 04–06 章）。
  • 用“状态 + 递推”的语言来写，就是动态规划（第 07–09 章）。
04

双指针：l 买，r 卖

用两个下标：r 是卖出日，从左往右每轮走一格，每一天都当一次卖出日；l 是买入日，始终指着 r 前面最便宜的那天。

l, r = 0, 1                  # l：买入日，r：卖出日
maxP = 0
while r < len(prices):
    if prices[l] < prices[r]:          # 今天卖能赚钱：算一下利润
        maxP = max(maxP, prices[r] - prices[l])
    else:                              # r 这天不比 l 贵：以后改在 r 买
        l = r
    r += 1
return maxP
  • l, r = 0, 1：先试“第 0 天买、第 1 天卖”。只有一天时 r = 1 已经不满足 r < len(prices)，循环一轮都不跑，返回 0。
  • r += 1 就是 r = r + 1。每轮结束 r 往右走一格，直到走过最后一天。
  • prices[l] < prices[r] 成立：今天卖比 l 那天买的贵，有利润，算一下，更新 maxP。l 不动，它还是最便宜的。
  • 不成立，说明 prices[r] ≤ prices[l]：r 这天比 l 还便宜（或一样）。以后不管哪天卖，从 r 买都至少和从 l 买一样好，所以 l = r。

为什么 l 能直接跳到 r

l = r 一下跳过了 l 和 r 之间好几天，它们会不会是更好的买入日？不会：

  • l 和 r 之间的每一天，价格都 ≥ prices[l]。如果其中某天比 prices[l] 便宜，r 走到那天时 l 早就跳过去了。
  • 现在 prices[r] ≤ prices[l]，所以那些天的价格也都 ≥ prices[r]。
  • 以后任何一个卖出日 k，从 r 买赚 prices[k] − prices[r]，至少和从那些天买一样多。所以它们永远不用再看。

l 一直指着最低价

每轮比较之前，下面这句话都成立：

prices[l] 是第 0 天到第 r − 1 天里的最低价。

  • 一开始 l = 0，r = 1：第 0 天到第 0 天只有一个数，就是 prices[0]，成立。
  • 每轮多看一天 prices[r]：它不比 prices[l] 便宜，最低价还是 prices[l]，l 不动；它更便宜（或一样），最低价换成它，l = r。r 往右走一格之后，这句话又成立了。

所以这段代码做的正是第 03 章的事：r 把每一天当一次卖出日，prices[l] 就是“r 之前的最低价”。

写成 l += 1 行不行？不行。题目的两个样例它都能过，但 [3, 5, 1, 4] 会返回 2，正确答案是 3（第 2 天买 1，第 3 天卖 4）。下一章可以单步看它在哪一步错的。

06
为什么没想到双指针

  
你之前做的双指针题，两个指针都是从两头往中间走（相向）。这道题两个指针都从左往右走（同向），而且 l 不是一格一格挪，是直接跳。长得不一样，所以不容易联想到。

  

    
题目指针怎么走每一步靠什么决定

    
验证回文串l 从左、r 从右，往中间走两头的字符是否相同

    
盛最多水的容器相向，每次挪矮的那边矮的那边决定了水位

    
三数之和固定一个数，另外两个相向三数之和偏大还是偏小

    
本题同向：r 每轮 +1；l 遇到更低价时跳到 rr 当卖出日，l 记住最便宜的买入日

  


  
同向双指针，也叫滑动窗口

  
NeetCode 把本题放在 Sliding Window（滑动窗口）分类。[l, r] 是一个窗口：r 每次往右扩一格；窗口左端“不划算”了（出现了更低的价格），就把 l 往右收。这一类后面还有“无重复字符的最长子串”“最长重复字符替换”。看到下面几个特征，就可以往同向双指针上想：

  
    
    
  • 题目要找的是一对 l < r，或者一段连续区间 [l, r]，而且有先后顺序。
    • 
    
  • 固定右端 r 之后，最好的左端能从之前记下的信息直接得到，不用回头重扫。
    • 
    
  • l 只会往右走，永远不需要往回退。
    • 
  


  
下次怎么想到

  
    
    
  1. 先写暴力双重循环：外层 i，内层 j。
    2. 
    
  2. 换个角度：固定 j，问最好的 i 是谁。
    3. 
    
  3. 如果“最好的 i”能随着 j 往右走顺手更新（本题是“到目前为止的最低价”），内层循环就可以删掉。
    4. 
  

  
没想到“双指针”这个名字也没关系。本题的 l 其实就是“最低价在哪一天”。只要想到“从左往右走，边走边记最低价”，就已经得到最优解了，它就是第 09 章的 DP 写法。







  
07
DP 从零开始：爬楼梯

  
动态规划（Dynamic Programming，DP）是一种解题思路：把大问题拆成同类的小问题，每个小问题只算一次、把答案存起来，大问题直接用存好的答案拼出来。先用最经典的一道题感受一下。

  

    
热身题：爬楼梯

    
一共 n 级台阶，每次可以爬 1 级或 2 级。爬到顶一共有多少种不同的爬法？例如 n = 3 有 3 种：1+1+1、1+2、2+1。

  

  
看最后一步。要站到第 n 级，最后一步只有两种可能：从第 n − 1 级跨 1 级上来，或者从第 n − 2 级跨 2 级上来。这两类爬法互不重复，加起来就是全部：

  
f(n) = f(n − 1) + f(n − 2)        f(1) = 1，f(2) = 2

  
f(n) 表示“爬到第 n 级有几种爬法”。最小的两个直接数：1 级只有一种（1）；2 级有两种（1+1 或 2）。照着公式写成函数：


def f(n):
    if n <= 2:
        return n               # f(1) = 1，f(2) = 2
    return f(n - 1) + f(n - 2)

  
    
    
  • def 定义一个函数。函数在自己里面调用自己，叫递归。
    • 
    
  • 递归必须有一个不再往下调用的出口，这里是 n <= 2。
    • 
  

  
这段代码是对的，但很慢。把它的调用过程画出来，每个圆圈是一次函数调用。选一个 n，再选一个 f(k) 高亮，看它被算了几次：

  

    

    

    

    
高亮的 f(k)虚线圆圈：f(1)、f(2)，直接返回，不再往下调用

    

  

  
同一个 f(k) 不管被谁调用，答案都一样，可递归每次都从头再算一遍。n 稍微大一点，调用次数就爆炸了：

算过的记下来：两种写法

  
写法一：记忆化递归（自顶向下）。还是递归，但每个结果第一次算出来就存进字典，下次直接拿。


memo = {}
def f(n):
    if n <= 2:
        return n
    if n in memo:              # 算过了，直接拿
        return memo[n]
    memo[n] = f(n - 1) + f(n - 2)
    return memo[n]

  
    
    
  • {} 是空字典，按 key 存值：memo[5] = 8 存，memo[5] 取。n in memo 检查有没有存过这个 key。
    • 
  

  
写法二：填表（自底向上）。干脆不递归，从小到大把每一格算出来。刷题时这种更常见。


if n <= 2:
    return n
dp = [0] * (n + 1)             # dp[i]：爬到第 i 级有几种爬法
dp[1], dp[2] = 1, 2
for i in range(3, n + 1):
    dp[i] = dp[i - 1] + dp[i - 2]
return dp[n]

  
    
    
  • [0] * (n + 1) 生成 n + 1 个 0 组成的列表，下标 0 到 n。dp[0] 用不到，留着是为了让下标正好等于台阶数。
    • 
    
  • for 循环从 3 填到 n。填 dp[i] 时，dp[i − 1] 和 dp[i − 2] 都已经填好了，直接用。每格只算一次，时间 O(n)。

DP 四步

  
不管什么 DP 题，都按这四步想。第一步最关键：状态定义清楚了，转移一般就是把“最后一步”的几种可能列出来。

  

    
步骤要回答的问题爬楼梯

    
1. 状态dp[i] 代表什么？用一句中文说清楚dp[i] = 爬到第 i 级的爬法数

    
2. 转移dp[i] 怎么用更小的格子算出来？看“最后一步”dp[i] = dp[i - 1] + dp[i - 2]

    
3. 初始值哪些格子没法用转移算，要直接写出来？dp[1] = 1，dp[2] = 2

    
4. 顺序与答案按什么顺序填？答案在哪一格？i 从 3 填到 n，答案 dp[n]

    
（可选）压缩转移只用到前面一两格吗？只用前两格，可以只留两个变量

  

  
能用 DP 的问题一般有两个特点：大问题的答案能由小问题的答案算出来；同一个小问题会被反复用到。第二个特点就是递归树里那些重复的紫色圆圈，DP 让每个只算一次。







  
08
用 DP 四步解本题

  
回到股票。按四步来：

  
1. 状态

  
    
    
  • dp[i]：买和卖都限定在第 0 天到第 i 天之间，最多能赚多少（不交易算 0）。
    • 
    
  • lo[i]：第 0 天到第 i 天里的最低价。转移要用到它，所以也存一张表。
    • 
  

  
2. 转移：看最后一天 i 做什么

  
    
    
  • 第 i 天不卖：交易全在前面的第 0 到 i − 1 天里完成，最多赚 dp[i - 1]。
    • 
    
  • 第 i 天卖：买入日在 i 之前，选最便宜的（第 03 章的结论），赚 prices[i] - lo[i - 1]。
    • 
    
  • 两种取大：
    • 
  

  
dp[i] = max( dp[i − 1], prices[i] − lo[i − 1] )
lo[i] = min( lo[i − 1], prices[i] )

  
第二行就是第 03 章那个“多考虑一个数”的递推，它本身也是一个小 DP。

  
3. 初始值

  
    
    
  • lo[0] = prices[0]：只有一天，最低价就是它。
    • 
    
  • dp[0] = 0：只有一天，没法卖，利润 0。
    • 
  

  
4. 顺序与答案

  
i 从 1 填到 n − 1，每一行只用上一行的格子。答案是 dp[n - 1]：允许用上全部日子时，最多能赚多少。


n = len(prices)
lo = [0] * n                 # lo[i]：第 0..i 天的最低价
dp = [0] * n                 # dp[i]：只在第 0..i 天交易，最多赚多少
lo[0] = prices[0]
for i in range(1, n):
    dp[i] = max(dp[i - 1], prices[i] - lo[i - 1])
    lo[i] = min(lo[i - 1], prices[i])
return dp[n - 1]

第 i 天prices[i]lo[i]最低价今天卖prices[i] − lo[i−1]dp[i]最多赚

09
两个变量：DP 就是双指针

  
DP 四步里的“压缩”：dp[i] 只用到 dp[i − 1] 和 lo[i − 1]，更早的格子再也不会用。所以不需要整张表，两个变量滚动更新就够了：


minBuy = prices[0]           # 到目前为止的最低价，相当于 lo[i - 1]
maxP = 0                     # 到目前为止最多赚多少，相当于 dp[i - 1]
for sell in prices:          # 每一天都当一次卖出日
    maxP = max(maxP, sell - minBuy)
    minBuy = min(minBuy, sell)
return maxP

  
    
    
  • for sell in prices: 直接拿到每天的价格，不需要下标。
    • 
    
  • 第一轮 sell = prices[0]，sell - minBuy 是 0，maxP 还是 0，没有影响，所以不用特意跳过第 0 天。
    • 
    
  • 先算利润，再更新最低价：算利润时用的是“今天之前”的最低价。两行换过来也对：先更新最低价，相当于允许同一天买卖，利润是 0，而答案本来就 ≥ 0。
    • 
    
  • 这就是 NeetCode 给出的 DP 解法，空间从 O(n) 降到 O(1)。
    • 
  


  
和双指针放在一起看

  
用例 1 [10, 1, 5, 6, 7, 1]，每个卖出日两种写法各自的变量（双指针取比较之前的 l，DP 取更新之前的 minBuy）：

  

    
卖出日 rprices[r]双指针的 lprices[l]DP 的 minBuymaxP

    
  

  
每一行 prices[l] 和 minBuy 都相等，maxP 也一样。l 记的是“最低价在哪一天”，minBuy 记的是“最低价是多少”，除此之外两段代码做的事完全相同：同一个 O(n) 算法的两种说法。


  
选读：按“手里有没有股票”分状态

  
股票系列后面还有好几道（可以买卖多次、有冷冻期、最多买卖两次……），它们通用的 DP 写法是按手里有没有股票分两种状态。本题也能这样写，先熟悉一下：

  
    
    
  • hold[i]：第 i 天结束时手里有股票，现金最多是多少。买入花的钱记成负数。
    • 
    
  • free[i]：第 i 天结束时手里没有股票，现金最多是多少。
    • 
  

  
hold[i] = max( hold[i − 1], −prices[i] )               昨天就拿着 / 今天买
free[i] = max( free[i − 1], hold[i − 1] + prices[i] )   昨天就空着 / 今天卖
初始值：hold[0] = −prices[0]，free[0] = 0；答案 free[n − 1]

  
“今天买”写成 −prices[i]：本题只能交易一次，买之前现金一定是 0。用例 1 填出来是这样：

  

    
第 i 天prices[i]hold[i]free[i]对照：−lo[i]对照：dp[i]

    
  

  
hold[i] 正好等于 −lo[i]，free[i] 正好等于 dp[i]。换了一种状态定义，算的还是同样的东西。到了可以买卖多次的 Best Time to Buy and Sell Stock II，只要把 −prices[i] 换成 free[i − 1] − prices[i]（卖掉之后可以用赚到的钱再买），其余不变。

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        minBuy = prices[0]               # 到目前为止的最低价
        maxP = 0                         # 到目前为止最多赚多少
        for sell in prices:
            maxP = max(maxP, sell - minBuy)
            minBuy = min(minBuy, sell)
        return maxP

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        l, r = 0, 1                      # l：买入日，r：卖出日
        maxP = 0
        while r < len(prices):
            if prices[l] < prices[r]:
                maxP = max(maxP, prices[r] - prices[l])
            else:
                l = r                    # 更便宜，以后改在这天买
            r += 1
        return maxP

最容易写错的五个地方

  
    
    
  • 直接 max(prices) - min(prices)：[10, 1, 5, 6, 7, 1] 得 9，忽略了先买后卖。
    • 
    
  • 双指针写成 l += 1：[3, 5, 1, 4] 返回 2，正确是 3。两个样例却都能过，交上去才发现错。
    • 
    
  • minBuy 初始化成 0：价格都 ≥ 0，最低价永远是 0，返回的是最高价（用例 1 返回 10）。要用 prices[0] 或 float("inf")（无穷大）。
    • 
    
  • maxP 初始化成 prices[1] - prices[0]：价格一路下跌时是负数，最后返回负数；只有一天时还会越界。要从 0 开始。
    • 
    
  • 暴力解内层写成 range(len(prices))：j 可以在 i 前面，等于允许先卖后买，结果和最高减最低一样错。
