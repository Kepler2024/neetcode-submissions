链表环检测

Linked List Cycle Detection。先看清“环”在链表里长什么样，为什么平常的遍历会停不下来。接着用哈希集合的笨办法打底，再讲快慢指针：为什么快的一定能追上慢的，为什么一次走两步刚好合适，循环条件为什么是 fast and fast.next。最后顺带讲怎么找出环从哪里开始。

题目

给你链表的头节点 head。如果链表里有环，返回 true，否则返回 false。

“有环”的意思是：顺着 next 一直走下去，会再次走到某个已经走过的节点。

判题系统内部用 index 表示尾节点的 next 接回第几个节点（从 0 数）。index = -1 表示尾节点的 next 是 null，没有环。注意：index 不会作为参数传给你。

输入: head = [1,2,3,4], index = 1 输出: true 输入: head = [1,2], index = -1 输出: false

约束：1 ≤ 链表长度 ≤ 1000，−1000 ≤ Node.val ≤ 1000，index 是 −1 或者一个合法下标。

01

环长什么样

链表的每个节点有两样东西：值 val，和指向下一个节点的 next。题目只给你头节点 head，其它节点都要顺着 next 一个一个走过去才能拿到。

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val      # 这个节点存的值
        self.next = next    # 下一个节点；没有下一个就是 None

平常遍历链表是这样写的，它靠“走到 None”停下来：

cur = head
while cur:              # cur 变成 None 才停
    cur = cur.next

题目的样例：尾节点 4 的 next 没有指向 None，而是接回了第 1 个节点（值为 2，从 0 数）。图里节点上方的 #0 #1 … 是节点的编号，紫色是环上的节点和接回去的那根箭头：

环上的节点尾节点接回去的箭头
情况一直 cur = cur.next 会怎样
没有环走完最后一个节点，cur 变成 None，循环结束
有环走到尾节点又被送回前面，在圈里转个不停，永远走不到 None
  • 所以普通遍历没法判断有没有环：没环时它会停，有环时它停不下来，程序卡死，你等不到一个“有环”的结论。
  • 有环的链表一定长成希腊字母 ρ 的样子：前面一段“尾巴”，后面一个圈。每个节点只有一个 next，所以一旦走进圈就再也出不来，圈后面不可能再挂别的节点。尾巴可以没有（index = 0，整条都是圈），圈也可以只有一个节点（尾节点指向自己）。
  • “走过的节点”指的是同一个节点，不是值相同的节点。[1,2,1,2] 里值有重复，但完全可以没有环。
  • 你拿不到 index，也拿不到长度（链表没有长度属性，有环时长度也没意义）。能做的只有顺着 next 走，看会不会回到走过的地方。
02

笨办法：记住走过的节点

最直接的想法：边走边把走过的节点记进一个集合。每到一个节点先查一下，以前来过就说明绕回来了，有环；走到 None 都没遇到来过的，就没环。

seen = set()
cur = head
while cur:
    if cur in seen:     # 第二次来到同一个节点：有环
        return True
    seen.add(cur)       # 记下这个节点（节点本身，不是 cur.val）
    cur = cur.next
return False            # 走到 None 了：没环

  • 存节点，不存值。Python 里自己定义的类（ListNode 没写 __eq__），放进 set 时按“是不是同一个对象”来比较，正好是我们要的。存 cur.val 的话，两个值相同的不同节点会被当成同一个，没环也会返回 True。
    • 
    
  • 每个节点最多进集合一次、查一次，时间 O(n)。但集合最多存 n 个节点，额外空间 O(n)。
    • 
    
  • 这个写法完全能通过，面试时也可以先说它。但面试官几乎一定会追问：能不能只用 O(1) 的额外空间？下一章就是答案。
    • 
  

  
还有个偷懒办法：约束说最多 1000 个节点，那就数步数，走了 1001 步还没到 None，一定有环。它能过，但完全依赖约束里的数字，换个约束就失效，面试时不算一个解法。







  
03
快慢指针：操场上跑圈

  
想象两个人同时从起点出发，一个跑得快，速度是另一个的两倍。

  
    
    
  • 如果路是一条直路，有终点：快的人先到终点，慢的人永远在他后面，两人不会再碰面。
    • 
    
  • 如果路的尽头是一个环形跑道：两人迟早都会跑进圈里。快的人在圈里一圈圈地跑，一定会从后面追上慢的人，也就是“套圈”。
    • 
  

  
链表里也一样，放两个指针：slow 每次走 1 步，fast 每次走 2 步。

  

    
发生了什么说明返回

    
fast 走到了 None路有尽头，没有环False

    
slow 和 fast 站到了同一个节点上fast 绕回来追上了 slow，有环True

  


slow, fast = head, head
while fast and fast.next:   # fast 前面还有至少两步的路
    slow = slow.next        # 慢的走 1 步
    fast = fast.next.next   # 快的走 2 步
    if slow == fast:        # 站到了同一个节点上
        return True
return False

  
这个方法叫 Floyd 判圈算法，也叫“龟兔赛跑”。它只用了两个变量，额外空间 O(1)。

04
为什么一定会相遇

  
分两段看。

  
第一段：slow 还在尾巴上

  
fast 跑得快，一定比 slow 先进圈。slow 走完尾巴的 a 步时，两个都已经在圈上了。

  
第二段：两个都在圈上，fast 追 slow

  
圈上没有“前后”，只有“追”。顺着箭头方向数，设 fast 还要走 d 步才到 slow 的位置，叫它差距（0 ≤ d < L）。每一轮：

  
    
    
  • slow 往前走 1 步，差距 +1；
    • 
    
  • fast 往前走 2 步，差距 −2；
    • 
    
  • 合起来，差距正好减少 1。
    • 
  

  
差距每轮少 1，从 d 一路减到 0，不可能跳过 0。差距变成 0 的那一刻，两个指针就站在同一个节点上。用题目样例 [1,2,3,4], index = 1（尾巴 a = 1，圈 L = 3）走一遍：

  

    
轮slowfast都在圈上？差距 d

    
开始1#01#0否—

    
12#13#2是2

    
23#22#1是1

    
34#34#3是0 相遇

  

  
第 1 轮 fast 在 #2，看起来在 slow 前面一格。但它是在圈上，顺着箭头 #2 → #3 → #1，要走 2 步才到 slow，所以差距是 2。第 2 轮 fast 绕过了尾节点，从 #2 走到 #3 再到 #1。

  
要跑多久

  
    
    
  • slow 进圈时差距 d < L，所以 slow 进圈后不到 L 轮就被追上，slow 在圈上连一整圈都跑不完。
    • 
    
  • 总轮数不超过 a + L = n（尾巴加圈正好是全部节点）。没有环时，fast 每轮走 2 步，大约 n/2 轮就走到 None。两种情况时间都是 O(n)。
    • 
  

  
为什么 fast 走 2 步，不走 3 步

  
fast 走 3 步的话，差距每轮减 2，可能会跳过 0。比如圈长 L = 4，差距从 1 开始：

  

    
fast 每轮走差距每轮减少差距变化（L = 4，从 1 开始）结果

    
2 步11 → 0下一轮就相遇

    
3 步21 → 3 → 1 → 3 → …永远踩不到同一个节点

  

  
差距减 2 时，奇数减 2 还是奇数，绕一圈（加 L = 4）也还是奇数，永远到不了 0。fast 在途中会“路过” slow 的节点，但每轮结束时都没停在那里，代码只在每轮结束时比较。走 2 步保证差距一次只少 1，一定能停在同一个节点上，也是最省事的选择。







  
05
循环条件和比较的位置


while fast and fast.next:

  
循环里要执行 fast = fast.next.next，也就是要先取 fast.next，再取 fast.next.next。这两步都要求“点号前面的东西不是 None”：

  

    
检查保护的是什么时候会是 None

    
fast取 fast.next 不报错链表长度是偶数：fast 一次跨两步，正好跨出末尾，或者 head 本身就是 None

    
fast.next取 fast.next.next 不报错链表长度是奇数：fast 停在最后一个节点上

  

  
    
    
  • and 是“短路”的：如果 fast 已经是 None，Python 就不会再去算 fast.next，所以不会报错。顺序不能反，写成 fast.next and fast，fast 是 None 时一上来就报错。
    • 
    
  • slow 不用检查：slow 走的路 fast 都走过，而且 fast 总在前面。fast 没出界，slow 就不可能出界。
    • 
    
  • 只写 while fast: 不够：奇数长度时 fast 停在最后一个节点，fast.next 是 None，再取 .next 就是 AttributeError。
    • 
  

  
比较放在移动之后

  
一开始 slow 和 fast 都在 head 上，本来就是同一个节点。如果先比较再走，第一轮就会返回 True，不管有没有环。所以要先走，再比较。

  
== 比的是什么

  
ListNode 没有定义 __eq__，slow == fast 比的是“是不是同一个节点”，和 slow is fast 一样。千万别写成 slow.val == fast.val：值相同的两个不同节点会被误判成相遇；fast 走到 None 时取 fast.val 还会报错。

  
这一章的三种写错法（只检查 fast、先比较再走、比较值），下一章都可以切换着跑一遍。

07
进阶：找到环的入口

  
本题只问有没有环。它的进阶版 Linked List Cycle II 还要你返回环从哪个节点开始（入口）。快慢指针相遇以后，再加几行就能找到。

  
还用第 03 章那个链表（a = 3，L = 6）。slow 和 fast 第 6 轮在 #6 相遇，它在入口 #3 之后 b = 3 步：

  

  
    
    
  • 相遇时 slow 走了 a + b 步，fast 走了它的两倍 2(a + b) 步。
    • 
    
  • fast 多走的那 a + b 步，全是在圈上多绕的整圈，所以 a + b = k·L（k 是某个正整数）。
    • 
    
  • 移项：a = k·L − b。从相遇点再往前走 a 步，等于先走 L − b 步回到入口，再绕 k − 1 个整圈，最后还停在入口。
    • 
    
  • 所以：一个指针放回 head，一个留在相遇点，两个都每次走 1 步。走 a 步后，从 head 出发的那个刚好走完尾巴到了入口，留在圈上的那个也刚好到了入口，它们就在入口相遇。
    • 
  


def detectCycle(head):
    slow, fast = head, head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:            # 第一段：相遇，说明有环
            p = head
            while p != slow:        # 第二段：都每次走 1 步
                p = p.next
                slow = slow.next
            return p                # 再次相遇的地方就是入口
    return None

  
图里正好 a = 3：从 head #0 走 3 步到 #3，从相遇点 #6 走 3 步（#7 → #8 → #3）也到 #3。







  
08
快慢指针模板与同类题

  
“一个走 1 步，一个走 2 步”是链表题里很常用的骨架：


slow, fast = head, head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    # 判环：在这里比较 slow == fast
# 循环结束时，没有环的话 slow 停在链表中间

  

    
题目和本题的关系

    
本题fast 追上 slow 就有环，fast 到 None 就没环

    
Linked List Cycle II相遇后一个回 head，同速再走一次，相遇处是入口（第 07 章）

    
Middle of the Linked Listfast 走到头时，slow 正好在中间

    
Reorder List先用快慢指针找中点，再反转后半段，最后交替接起来

    
Palindrome Linked List找中点，反转后半段，和前半段逐个比较

    
Find the Duplicate Number把数组看成链表 i → nums[i]，重复的数就是环的入口，正好用第 07 章的方法

    
Happy Number不断算“各位数字平方和”，要么到 1，要么进入循环。用快慢指针判圈，不用集合

  

  
下次怎么想到

  
    
    
  1. 看到“会不会重复/会不会绕回来”：第一反应是用集合记住来过的，能过但要 O(n) 空间。
    2. 
    
  2. 被要求 O(1) 空间，而且每个位置只有唯一的“下一个”（链表的 next、函数 f(x)）：用快慢指针，快的走 2 步、慢的走 1 步。
    3. 
    
  3. 循环条件写 fast and fast.next，先走再比较，比较的是节点本身。

完整代码与复杂度

  

    
    
    
  

  

    
快慢指针（推荐）


class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow, fast = head, head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow == fast:
                return True
        return False

    
哈希集合


class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        seen = set()
        cur = head
        while cur:
            if cur in seen:
                return True
            seen.add(cur)
            cur = cur.next
        return False

  

  

    
快慢指针（推荐）


public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true;
        }
        return false;
    }
}

    
哈希集合


public class Solution {
    public boolean hasCycle(ListNode head) {
        Set<ListNode> seen = new HashSet<>();
        for (ListNode cur = head; cur != null; cur = cur.next) {
            if (!seen.add(cur)) return true;   // add 返回 false 说明已经在里面
        }
        return false;
    }
}

  

  

    
快慢指针（推荐）


class Solution {
public:
    bool hasCycle(ListNode* head) {
        ListNode* slow = head;
        ListNode* fast = head;
        while (fast != nullptr && fast->next != nullptr) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) return true;
        }
        return false;
    }
};

    
哈希集合


class Solution {
public:
    bool hasCycle(ListNode* head) {
        unordered_set<ListNode*> seen;
        for (ListNode* cur = head; cur != nullptr; cur = cur->next) {
            if (seen.count(cur)) return true;
            seen.insert(cur);
        }
        return false;
    }
};

  

  
Optional[ListNode] 是类型提示，意思是“一个 ListNode 或者 None”。Java 里对象用 == 比较的是“是不是同一个对象”，C++ 里比较的是两个指针存的地址，都正好是“同一个节点”的意思。Java 的 seen.add(cur) 在元素已经存在时返回 false，可以把“查”和“加”合成一步。


  
复杂度（n 是节点个数）

  

    
解法时间额外空间说明

    
哈希集合O(n)O(n)每个节点进集合一次

    
快慢指针O(n)O(1)有环时不超过 n 轮，没环时约 n/2 轮

  


  
最容易写错的五个地方

  
    
    
  • 循环条件只写 while fast:：奇数长度的无环链表，fast 停在最后一个节点，fast.next.next 报 AttributeError。
    • 
    
  • 先比较再走：slow 和 fast 一开始都在 head，第一轮就返回 True。
    • 
    
  • 比较 slow.val == fast.val：[2,3,3,4] 没有环，第一轮 slow 在第一个 3、fast 在第二个 3，值相等就误判成 True。
    • 
    
  • 哈希集合里存 cur.val：同样的问题，[1,2,1,3] 没有环也返回 True。
    • 
    
  • 写成 fast = slow.next.next 之类的笔误：fast 不再是“每轮比 slow 多走 1 步”，差距不会稳定地减 1，可能永远追不上。
