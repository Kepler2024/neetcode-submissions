三数之和

3Sum。这一页从“列表和下标”讲起，先写出三重循环的暴力解，再讲排序和集合去重、有序数组上的双指针，然后把三数之和拆成“固定一个数 + 两数之和”，最后处理最容易写错的去重，走到 O(n²) 的标准解法。每一章只讲一个前置知识，所有 Python 语法都会单独解释。

题目

给你一个整数数组 nums，返回所有满足 nums[i] + nums[j] + nums[k] == 0 的三元组 [nums[i], nums[j], nums[k]]，其中下标 i、j、k 互不相同。

答案中不能包含重复的三元组。三元组之间的顺序、每个三元组内部的顺序都可以任意。

输入: nums = [-1,0,1,2,-1,-4] 输出: [[-1,-1,2],[-1,0,1]] 解释: nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0 nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0 nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0 不同的三元组是 [-1,0,1] 和 [-1,-1,2] 输入: nums = [0,1,1] 输出: [] 解释: 唯一的三元组加起来不等于 0

约束：3 ≤ nums.length ≤ 1000，-10⁵ ≤ nums[i] ≤ 10⁵。

01

列表、下标与三元组

Python 的列表（list）是一串按顺序排好的值，用方括号写。每个位置有一个下标，从 0 开始：

nums = [-1, 0, 1, 2, -1, -4]
len(nums)      # 6，一共 6 个数
nums[0]        # -1
nums[4]        # -1，值和 nums[0] 一样，但它是另一个位置
nums[-1]       # -4，负数下标从后往前数，-1 是最后一个
  • 三元组就是三个数组成的小列表，比如 [-1, 0, 1]。本题的答案是“装着若干个三元组的列表”，也就是列表里套列表：[[-1, -1, 2], [-1, 0, 1]]。一个都找不到时返回空列表 []。
  • res = [] 创建一个空列表；res.append(x) 把 x 加到末尾。res.append([1, 2, 3]) 加进去的是一整个小列表，res 的长度只加 1。

题目里的两个“不同”，意思不一样

题目的说法指的是例子
下标 i、j、k 互不相同位置不同，值可以相同nums[0] 和 nums[4] 都是 -1，是两个位置，可以一起用，得到 [-1, -1, 2]
不能有重复的三元组只看值，不看位置，也不看顺序下标 (0, 1, 2) 和 (1, 2, 4) 选出来的都是 -1、0、1，只能算一组

02

暴力解：三重循环

最直接的想法：把“选三个不同位置”的所有方式都试一遍，加起来等于 0 就记下来。

n = len(nums)
for i in range(n):
    for j in range(i + 1, n):
        for k in range(j + 1, n):
            if nums[i] + nums[j] + nums[k] == 0:
                print(i, j, k)
  • range(n) 依次产生 0, 1, …, n-1；range(a, n) 从 a 开始，同样到 n-1 为止，不包含 n。比如 list(range(2, 5)) 是 [2, 3, 4]。
  • for x in range(...): 让 x 依次取这些值，每取一个，就把下面缩进的代码执行一遍。三层 for 套在一起时，外层每走一步，里面两层都要从头完整走一遍。
  • j 从 i + 1 开始，k 从 j + 1 开始，保证了 i < j < k。这样三个下标一定互不相同，而且同一组位置只会被试一次：(0, 1, 2) 和 (1, 0, 2) 是同样三个位置，只试前一种就够。

以 n = 4 为例，三重循环依次试的是：

一共 4 组，正好是“从 4 个里选 3 个”的组合数 C(4, 3)。

问题一：太慢

n 个数里选 3 个，一共 C(n, 3) = n(n-1)(n-2) / 6 种，大约 n³ / 6，时间复杂度 O(n³)。n = 1000 时约 1.66 亿种组合，Python 一秒大约只能做几千万次这样的简单运算，会超时。

问题二：重复

在示例 1 上跑，和为 0 的有三组：

(i, j, k)选出的值和
(0, 1, 2)[-1, 0, 1]0
(0, 3, 4)[-1, 2, -1]0
(1, 2, 4)[0, 1, -1]0

第一组和第三组是同样三个数，只是顺序不同。题目要求不重复，只能留一个。下一章先用排序和集合解决重复，第 04 章开始解决慢。

03

排序与集合去重

排序：sort 和 sorted

nums = [-1, 0, 1, 2, -1, -4]
nums.sort()            # 原地排序，nums 本身被改掉了
nums                   # [-4, -1, -1, 0, 1, 2]

b = sorted([3, 1, 2])  # 返回一个新的有序列表，原来的列表不变
b                      # [1, 2, 3]
  • nums.sort() 直接修改 nums，返回值是 None（Python 里表示“没有值”）。常见错误是写成 nums = nums.sort()，结果 nums 变成了 None。
  • 排序花 O(n log n) 时间。后面的算法是 O(n²)，n log n 比 n² 小，排序不影响总复杂度。
  • 排好序之后，i < j < k 就意味着 nums[i] ≤ nums[j] ≤ nums[k]：每个三元组都按从小到大的顺序被选出来。同样三个数，写出来的样子就完全一样了。上一章的 [-1, 0, 1] 和 [0, 1, -1] 都会变成 [-1, 0, 1]。

集合 set 与元组 tuple

集合（set）是一种不允许重复的容器：同一个值放两次，里面也只有一个。

seen = set()             # 空集合。注意 {} 是空字典，不是空集合
seen.add((-1, 0, 1))
seen.add((-1, 0, 1))     # 已经有了，不会再多一个
len(seen)                # 1

seen.add([-1, 0, 1])     # TypeError: unhashable type: 'list'
  • (-1, 0, 1) 用圆括号，叫元组（tuple）。它和列表很像，区别是创建之后不能修改。set 只能装不能修改的值，所以列表要先用 tuple(lst) 转成元组再放进去。反过来，list(t) 把元组转回列表。
  • set 判断“重复”是逐个位置比较：(-1, 0, 1) 和 (0, 1, -1) 在它眼里是两个不同的元组。所以必须先排序，set 去重才有效。
  • [list(t) for t in seen] 叫列表推导式，读作“对 seen 里的每个 t，取 list(t)，收集成一个新列表”。

暴力解完整代码

res = set()
nums.sort()
for i in range(len(nums)):
    for j in range(i + 1, len(nums)):
        for k in range(j + 1, len(nums)):
            if nums[i] + nums[j] + nums[k] == 0:
                res.add((nums[i], nums[j], nums[k]))
return [list(t) for t in res]

在下面输入数组，看三重循环试过的每一组。先不勾选“先排序”，看 set 为什么会去重失败，再勾上对比。点表格的一行，上方会标出这一组选中的格子：

#(i, j, k)三个数和说明

暴力解是对的，但 O(n³) 太慢，set 还要额外的空间。接下来三章把它降到 O(n²)：先学有序数组上找两个数的双指针（第 04 章），再把三数之和拆成“固定一个数 + 两数之和”（第 05 章），最后不靠 set 去重（第 06 章）。

04

有序数组的两数之和

先放下三数之和，看一个更简单的问题：数组已经从小到大排好，找出所有和等于 target 的两个数（两个下标不同）。

用双指针：左指针 l 从最左边（最小的数）出发，右指针 r 从最右边（最大的数）出发，每次看 nums[l] + nums[r]：

情况做法原因
和 < targetl += 1和太小，要换一个更大的数。只有 l 往右挪，和才会变大
和 > targetr -= 1和太大，要换一个更小的数。只有 r 往左挪，和才会变小
和 == target记下来，l += 1 且 r -= 1这两个数都用过了，同时往中间走，继续找
l, r = 0, len(nums) - 1
while l < r:
    s = nums[l] + nums[r]
    if s > target:
        r -= 1
    elif s < target:
        l += 1
    else:
        pairs.append([nums[l], nums[r]])
        l, r = l + 1, r - 1
  • while 条件: 只要条件为真，就一直重复下面缩进的代码，每一轮开始前都会重新检查条件。
  • if / elif / else 从上往下检查，第一个成立的分支执行，其余的跳过。elif 是 “else if” 的缩写。这里三种情况互不重叠，每轮必定执行其中恰好一个。
  • l, r = 0, len(nums) - 1 是同时赋值：先把右边的值都算好，再依次交给左边的变量。l, r = l + 1, r - 1 就是“l 加一、r 减一”。
  • 条件是 l < r 而不是 l <= r：l == r 时两个指针在同一个位置，同一个数不能用两次。

为什么挪指针不会漏掉答案

以 nums = [-4, -2, 0, 1, 3, 6]、target = 1 为例。一开始 nums[l] + nums[r] = (-4) + 6 = 2，太大了。

6 是当前范围里最大的数，-4 是最小的数。6 和最小的 -4 配都已经超过 1 了，和范围里任何别的数配只会更大。所以 6 不可能出现在任何一个答案里，可以放心扔掉，r -= 1。

反过来也一样：和太小时，nums[l] 和最大的 nums[r] 配都不够，和谁配都不够，扔掉 nums[l]。

每一步至少扔掉一个数，范围从 n 个一路缩到不足两个，所以最多走 n 步，时间 O(n)，比两层循环试所有的对（O(n²)）快得多。这一切都靠数组有序。

06
跳过重复值

  
排好序后，相同的值都挨在一起。重复的三元组只会从两个地方来：nums[i] 和上一轮相同，或者找到一组之后 nums[l] 还是同一个值。


  
来源一：nums[i] 和上一个相同


if i > 0 and nums[i] == nums[i - 1]:
    continue

  
    
    
  • continue：立刻结束这一轮循环，直接进入下一轮（i 加一），下面的代码这一轮都不执行。
    • 
    
  • 为什么可以跳过：nums[i] 和 nums[i - 1] 值相同，而 nums[i - 1] 当第一个数时，可以挑的范围（i - 1 右边）比 nums[i] 的还多一个位置。nums[i] 能找到的组合，上一轮全都找过了。
    • 
    
  • i > 0 不能省：i = 0 时 nums[i - 1] 就是 nums[-1]，也就是最后一个数，Python 不会报错。nums = [0, 0, 0] 时，i = 0 会拿第一个 0 和最后一个 0 比，误以为重复而跳过，最后返回 []。
    • 
    
  • A and B 两边都真才是真，Python 从左往右算，A 为假时根本不会去算 B，这叫短路。写了 i > 0，i = 0 时就不会去读 nums[-1]。
    • 
  


  
为什么和前一个比，而不是和后一个比

  
看 nums = [-1, -1, 2]：

  

    
写法过程结果

    
nums[i] == nums[i - 1]i = 0 不检查，固定第一个 -1，l 用第二个 -1，找到 [-1, -1, 2]；i = 1 和前一个相同，跳过[[-1, -1, 2]]

    
nums[i] == nums[i + 1]i = 0 时第一个 -1 和后一个相同，被跳过；i = 1 时右边只剩一个 2，凑不出[]，漏了

  

  
和前一个比的意思是：每个值只在第一次出现时当 nums[i]，这时它右边还能用上和它相同的数。和后一个比恰好反过来，留下的是最后一次出现，右边已经没有同值的数了（而且 i 走到最后一个时，nums[i + 1] 还会越界）。


  
来源二：找到一组后，nums[l] 还是同一个值

  
看 nums = [-2, 0, 0, 2, 2]，i = 0：

  

    
lrtotal发生了什么

    
14(-2) + 0 + 2 = 0找到 [-2, 0, 2]，l、r 变成 2、3

    
23(-2) + 0 + 2 = 0又是 [-2, 0, 2]，重复了

  

  
办法：找到一组、两个指针往中间走之后，如果新的 nums[l] 和刚用过的 nums[l - 1] 相同，就继续往右跳：


res.append([nums[i], nums[l], nums[r]])
l, r = l + 1, r - 1
while l < r and nums[l] == nums[l - 1]:
    l += 1

  
    
    
  • 这里用 while 而不是 if：可能连着好几个相同的值，要一直跳到不同为止。上面的例子里，l 从 2 跳到 3，这时 l == r，循环结束，不会再找到第二次。
    • 
    
  • 守卫 l < r 写在前面，和外层的 i > 0 是一个道理。不写它，[0, 0, 0] 找到一组后 l = 2、r = 1，nums[2] 和 nums[1] 相同，l 变成 3，再去读 nums[3] 就报 IndexError: list index out of range。
    • 
    
  • r 不用跳：l 跳到一个更大的值之后，如果 nums[r] 还是旧值，total = nums[i] + 更大的 nums[l] + nums[r] 一定大于 0，下一轮自然会执行 r -= 1。重复的 r 会被正常流程挪走，凑不出同一组。（对称地也写一个跳过 r 的 while，结果一样。）
    • 
    
  • 只在找到答案之后才需要跳。total 不等于 0 时，就算遇到重复值也只是多比较一次，不会产生重复答案。
    • 
  


  
提前结束：nums[i] > 0 就 break


if nums[i] > 0:
    break

  
排序后 nums[i] 右边的数都 ≥ nums[i]。如果 nums[i] 已经大于 0，三个数都是正数，加起来不可能等于 0，后面的 i 只会更大。这一句不写也对，但能省时间。

  

    
语句作用本题里用在哪

    
continue结束这一轮，进入下一轮nums[i] 是重复值：这个 i 不用看，下一个 i 可能有用

    
break结束整个循环nums[i] > 0：这个 i 和后面所有的 i 都不可能

class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        res = []
        nums.sort()                                    # 排序：双指针和去重的前提

        for i in range(len(nums)):
            if nums[i] > 0:                            # 最小的数都大于 0，不可能凑出 0
                break
            if i > 0 and nums[i] == nums[i - 1]:       # 和上一个固定的数相同，跳过
                continue

            l, r = i + 1, len(nums) - 1
            while l < r:
                total = nums[i] + nums[l] + nums[r]
                if total > 0:                          # 太大：右指针左移
                    r -= 1
                elif total < 0:                        # 太小：左指针右移
                    l += 1
                else:                                  # 找到一组
                    res.append([nums[i], nums[l], nums[r]])
                    l, r = l + 1, r - 1
                    while l < r and nums[l] == nums[l - 1]:  # 跳过重复的 nums[l]
                        l += 1

        return res


class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> res = new ArrayList<>();

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] > 0) break;
            if (i > 0 && nums[i] == nums[i - 1]) continue;

            int l = i + 1, r = nums.length - 1;
            while (l < r) {
                int total = nums[i] + nums[l] + nums[r];
                if (total > 0) {
                    r--;
                } else if (total < 0) {
                    l++;
                } else {
                    res.add(Arrays.asList(nums[i], nums[l], nums[r]));
                    l++;
                    r--;
                    while (l < r && nums[l] == nums[l - 1]) l++;
                }
            }
        }
        return res;
    }
}

                    l++;
                } else {
                    res.push_back({nums[i], nums[l], nums[r]});
                    l++;
                    r--;
                    while (l < r && nums[l] == nums[l - 1]) l++;
                }
            }
        }
        return res;
    }
};

  
class Solution: 和 def threeSum(self, nums: List[int]) -> List[List[int]]: 是 NeetCode 给定的外壳。List[int] 表示整数列表，List[List[int]] 表示“列表的列表”，这些只是类型提示，不影响运行。NeetCode 官方题解写的是 for i, a in enumerate(nums):，enumerate 每次同时给出下标 i 和值 a（也就是 nums[i]），和本页的写法等价。

  
复杂度

  

    
解法时间额外空间说明

    
三重循环 + setO(n³)O(m)m 是答案个数，set 要存下所有三元组

    
固定一个数 + 哈希表O(n²)O(n)用 Two Sum 的哈希表找另外两个数，去重更麻烦

    
排序 + 双指针O(n²)O(1)不计排序和答案本身，只用了 i、l、r 几个变量

  

  
时间：排序 O(n log n)，外层 n 轮、每轮双指针最多 n 步是 O(n²)，n² 比 n log n 大，所以总的是 O(n²)。n = 1000 时双指针大约走 50 万步，而暴力解要试 1.66 亿组。

  
空间：排序本身可能用到额外空间，Python 的 sort 最坏要 O(n)，Java、C++ 对整数排序一般是 O(log n)。所以很多题解会写“O(1) 或 O(n)，取决于排序算法”。

  
最容易写错的六个地方

  
    
    
  • 写成 nums = nums.sort()：sort() 返回 None，nums 变成 None，下一行就报错。
    • 
    
  • 外层去重漏了 i > 0：[0, 0, 0] 在 i = 0 时就拿 nums[-1] 比较，返回 []。
    • 
    
  • 写成 nums[i] == nums[i + 1]：[-1, -1, 2] 会漏掉 [-1, -1, 2]。
    • 
    
  • 找到一组后忘了移动指针：total 一直是 0，同一组被反复加进 res，死循环。
    • 
    
  • 内层写成 while l <= r：l == r 时同一个数被用了两次。[-2, 1, 3] 会错误地得到 [[-2, 1, 1]]。
    • 
    
  • 跳过重复的 while 没写 l < r：[0, 0, 0] 报 IndexError。
